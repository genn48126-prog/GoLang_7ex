Сервис выступает в роли API-шлюза для микросервиса Ledger. 

Он принимает входящие HTTP-запросы от клиентов на порту `8080` и перенаправляет их на внутренний сервис Ledger (порт `8081`), скрывая внутреннюю архитектуру.

## Роль в проекте

Раньше Gateway и Ledger могли работать с данными в памяти. Теперь Gateway обращается к тем же HTTP-эндпойнтам, но Ledger хранит данные в PostgreSQL. Gateway при этом остается "тонким" клиентом и не требует изменений в логике маршрутизации, он просто проксирует запросы к обновленному Ledger.

## Требования

*   Запущенный сервис (должен слушать порт `8081`).
